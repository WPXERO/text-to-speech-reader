# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WPXERO Text to Speech — the **core** (free, WordPress.org-bound) plugin. PHP namespace `TTSR`, prefix `ttsr_`. Reads post content aloud with the browser Web Speech API: no remote requests, accounts, telemetry or remote code. A standard self-contained plugin directory in `wp-content/plugins/wpxero-text-to-speech/` — not part of a monorepo/workspace, and it should stay that way.

A separate add-on, WPXERO Text to Speech Pro, lives in the sibling checkout `../wpxero-text-to-speech-pro` (own repo). It contains no copy of core code and extends this plugin only at runtime through the contract in `docs/integration-api.md`. Core changes can break Pro: its typecheck imports core types from this checkout, its unit tests mount this plugin's real player, and its `test:wp` re-runs this plugin's `tests/php/free.php` with Pro active.

Docs: `docs/architecture.md` (feature matrix, class responsibilities, security, data lifecycle), `docs/integration-api.md` (extension contract + compatibility matrix), `docs/testing.md` (suites, latest results, manual checklist), `docs/audit.md` (the `text-to-audio` plugin this was reimplemented from and which features were kept, moved to Pro or deliberately removed). User-facing docs are in `readme.txt`.

## Commands

Requirements: Node 22.22+/24.15+/26+, PHP 7.4+ with Composer, `zip`/`unzip`, WP-CLI.

```bash
npm install && composer install && npm run build   # setup
npm run start            # watch build
npm run build            # production build → build/
npm run typecheck        # tsc — Babel only strips types, so this is the real type check
npm run lint             # typecheck + ESLint + Stylelint + php -l + PHPCS (WPCS + PHPCompatibilityWP 7.4+)
composer lint:fix        # phpcbf auto-fix
npm run format           # Prettier (WordPress config)
npm test                 # Vitest (jsdom), tests/js/**/*.test.ts(x)
npx vitest run tests/js/engine.test.ts   # single file
npx vitest run -t "pause"                # tests matching a name
WP_CLI="wp --path=/path/to/wordpress" npm run test:wp   # PHP integration tests in a real WP install
npm run check-versions   # all version strings agree
npm run makepot          # languages/wpxero-text-to-speech.pot (needs WP-CLI)
npm run package && npm run verify-package   # dist/wpxero-text-to-speech.zip + validation
npm run release          # all of the above in order (test:wp only if WP_CLI is set); never tags or publishes
wp plugin check wpxero-text-to-speech --include-experimental   # Plugin Check on the unzipped package before release
```

`test:wp` rewrites the `active_plugins` option to activate the plugin and restores it afterwards — run it only against a disposable site. The PHP integration tests are not PHPUnit: `tests/php/free.php` is run with `wp eval-file` using the assertion harness in `tests/php/bootstrap.php` (`ttsr_test_group()`, `ttsr_assert()`); tests create and delete their own posts and must pass whether or not Pro is active.

`src/admin-ui/icon-data.ts` is generated by `bin/icons.mjs` from Material Symbols — don't hand-edit; the script header says how to regenerate.

## Architecture

**PHP** (`includes/`, one class per responsibility). `Plugin` is the service container (`ttsr()`), and fires `ttsr_loaded` on `plugins_loaded` priority 5 — that's where extensions boot.

* `Content_Integration` filters `the_content` at priority 20 (after blocks/shortcodes), only for the main query of a singular view — never feeds, REST, admin, archives or password-protected posts. `Renderer` outputs the player container + JSON config and has a per-request guard against a second automatic player for the same post. Manual placement goes through `Shortcode` (`[wpxero_text_to_speech]`) and `Block`.
* `Settings` (option `ttsr_settings`) validates key by key. Values supplied by an extension that is now inactive (layout, placement, post type) are preserved on save but not newly accepted. The JS validators in `src/utils/validation.ts` mirror the PHP sanitisers — keep them in sync.
* `Rest_Controller` serves `ttsr/v1/settings` (+ `/settings/reset`), `manage_options` only.
* `blocks/player/block.json` lives outside `src/` and is registered from PHP, which is why `webpack.config.js` drops the default `CopyPlugin`/`PhpFilePathsPlugin`.

**Frontend player** (`src/player`) is dependency-free TypeScript; React runs only in wp-admin. `extract.ts` builds text blocks mapped back to text nodes and never mutates the article DOM. `chunks.ts` splits sentences (`Intl.Segmenter`, regex fallback, <200 chars). `engine.ts` is the single `SpeechEngine` per page: pause cancels and remembers the last word boundary, resume restarts from it, and a generation counter turns callbacks from cancelled utterances into no-ops. `api.ts` exposes `window.TTSR` (handle `ttsr-player`); Pro features drive this engine rather than adding a second one.

**Admin** (`src/admin`, React): hash-routed settings sections over an external REST-backed store; the preview mounts the real frontend player. Extensible via `@wordpress/hooks` filters `ttsr.admin.*` (sections, groups, preview).

**Shared admin UI library** (`src/admin-ui`): components, store helper and validation, built as a separate webpack entry exposed as `window.ttsr.adminUi` with handle `ttsr-admin-ui`. `webpack.config.js` replaces the default `DependencyExtractionWebpackPlugin` with one mapping `@ttsr/admin-ui` → that global/handle, so the settings app and Pro share one copy per page. In tests, `vitest.config.mjs` aliases `@ttsr/admin-ui` to the source.

**Extension contract.** PHP hooks (`ttsr_player_config`, `ttsr_player_style`, `ttsr_insert_player`, `ttsr_should_auto_insert`, …), `window.TTSR`, and `ttsr-admin-ui`. Extension data in player config goes under `extensions.{prefix}`. New shared functionality belongs here in the core, exposed through one of those surfaces. Any contract change must be reflected in `docs/integration-api.md`. Bump `TTSR_API_VERSION` **only** for breaking changes — Pro boots only if `TTSR_VERSION >= TTSRP_REQUIRES_FREE` and `TTSR_API_VERSION === TTSRP_REQUIRES_API`; additive hooks/config keys don't change it.

**Output safety.** Style vars printed on the player are restricted to `--ttsr-*`/`--ttsrp-*` names with simple values; user CSS selectors are restricted to a safe character set and used only inside `try` with `querySelectorAll`/`matches`.

## Packaging and releasing

Only runtime files ship: plugin file, `uninstall.php`, `readme.txt`, `LICENSE.txt`, `includes/`, `blocks/`, `build/`, `languages/` — `verify-package` enforces this. A version bump touches the plugin header, `TTSR_VERSION`, `readme.txt` (Stable tag + changelog), `blocks/player/block.json` and `package.json`; `npm run check-versions` catches mismatches. A new Pro release also adds a compatibility-matrix row in `docs/integration-api.md`.

Releases are cut by pushing a `vX.Y.Z` tag matching the plugin version; `.github/workflows/release.yml` verifies, builds, tests, packages and creates the GitHub Release. Its WordPress.org SVN deploy stays off until the repo variable `WPORG_DEPLOY` is `true` (see README). `ci.yml` runs build/lint/test/package on every push.
