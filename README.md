# WPXERO Text to Speech

Development README for the WordPress plugin. User documentation is in
`readme.txt`. The plugin reads content aloud with the browser's Web Speech
API; it needs no account or API key and makes no remote requests.

[WPXERO Text to Speech Pro](../wpxero-text-to-speech-pro) is a separate
add-on that extends this plugin through the documented extension API.

* [docs/architecture.md](docs/architecture.md) — feature matrix, code structure, security and data lifecycle.
* [docs/integration-api.md](docs/integration-api.md) — the extension contract (PHP hooks, `window.TTSR`, the `ttsr-admin-ui` library, version compatibility).
* [docs/testing.md](docs/testing.md) — test suites, latest results, what still needs manual verification.
* [docs/audit.md](docs/audit.md) — audit of the `text-to-audio` plugin this project was derived from.

## Layout

```
wpxero-text-to-speech.php   Plugin header, constants, bootstrap
uninstall.php               Data removal (opt-in)
includes/                   PHP classes (namespace TTSR)
blocks/player/block.json    Block metadata (registered from PHP)
src/
  player/                   Frontend player, window.TTSR (no dependencies)
  admin/                    Settings app (React)
  admin-ui/                 Admin UI library → handle ttsr-admin-ui, window.ttsr.adminUi
  block/  editor/           Block and document settings panel
  utils/  types.ts          Validation helpers and shared types
build/                      Compiled assets (generated by npm run build)
languages/                  .pot (generated by npm run makepot)
tests/js/  tests/php/       Vitest unit tests, WordPress integration tests
bin/                        Build, packaging and test scripts
```

Only the runtime files (the plugin file, `uninstall.php`, `readme.txt`,
`LICENSE.txt`, `includes/`, `blocks/`, `build/`, `languages/`) go into the
package; everything else is development tooling.

## Prerequisites

* Node.js 22.22+, 24.15+ or 26+ (required by `@wordpress/scripts` 37) and npm
* PHP 7.4+ with Composer (for PHPCS)
* `zip` and `unzip`
* WP-CLI (for `makepot` and the integration tests) and a disposable WordPress site for `test:wp`

## Setup

Work in the plugin directory inside a site's `wp-content/plugins`:

```bash
npm install
composer install
npm run build
```

## Commands

```bash
npm run start            # watch build
npm run build            # production build → build/
npm run typecheck        # tsc --noEmit
npm run lint             # tsc + ESLint + Stylelint + php -l + PHPCS
npm run format           # Prettier (WordPress config)
npm test                 # Vitest unit tests
npx vitest run tests/js/engine.test.ts   # a single test file
npx vitest run -t "pause"                # tests matching a name
WP_CLI="wp --path=/path/to/wordpress" npm run test:wp   # integration tests in WordPress
npm run makepot          # languages/wpxero-text-to-speech.pot (needs WP-CLI)
npm run package          # dist/wpxero-text-to-speech.zip
npm run verify-package   # validate the ZIP
npm run release          # everything above in order; prints the ZIP path
```

`test:wp` activates the plugin for the run and restores the previous plugin
state afterwards, so use a test site.

## Build notes

* One `@wordpress/scripts` build (webpack + Babel TypeScript), configured in
  `webpack.config.js`. React and `@wordpress/*` are externals; dependencies
  are written to `build/*.asset.php` and used when registering scripts.
* `admin-ui` is built as a library (`window.ttsr.adminUi`). The settings app
  imports it as `@ttsr/admin-ui`, which the build maps to that global and to
  the `ttsr-admin-ui` handle, so the app and extensions share one copy.
* TypeScript is type-checked separately with `tsc` (Babel only strips types).
* The public player is dependency-free TypeScript. React runs only in wp-admin.

## Releasing

1. Bump the version in the plugin header, `TTSR_VERSION`, `readme.txt`
   (`Stable tag` and changelog), `blocks/player/block.json` and
   `package.json`. Change `TTSR_API_VERSION` only for breaking changes to the
   extension contract.
2. `npm run release` (with `WP_CLI` set to also run the integration tests).
3. Run Plugin Check on the unzipped package
   (`wp plugin check wpxero-text-to-speech`) and work through the manual
   checklist in `docs/testing.md`.

4. Commit, then push a tag matching the version:
   `git tag v1.0.1 && git push origin v1.0.1`. The Release workflow
   (`.github/workflows/release.yml`) checks that the tag matches the plugin
   version, builds, lints, tests and packages the plugin, and creates a
   GitHub Release with the ZIP attached.

`.github/workflows/ci.yml` builds, lints, tests and uploads the ZIP as an
artifact on every push; it holds no credentials.

**WordPress.org deploy** is part of the Release workflow but off until the
plugin is approved on WordPress.org. To enable it, set the repository
variable `WPORG_DEPLOY` to `true` and create an environment named
`wordpress.org` with the secrets `SVN_USERNAME` and `SVN_PASSWORD` (add
required reviewers there to approve each deploy). Plugin page assets
(icons, banners, screenshots) go in `.wordpress-org/`. The deploy uses the
verified release package, so trunk and the version tag in SVN contain
exactly what is in the ZIP.

Before the first WordPress.org submission, add a `Contributors:` line with
the WordPress.org username(s) to `readme.txt`.
